# Phenobase Interface

[![Netlify Status](https://api.netlify.com/api/v1/badges/db775c45-a020-414c-9bba-539bf5de3fcf/deploy-status)](https://app.netlify.com/projects/phenobase2/deploys)

Lightweight web UI for searching and exploring plant phenology records in Phenobase.

Live site: <https://phenobase.netlify.app/>

## Application Environment

- App type: static frontend (HTML/CSS/JS, jQuery, Leaflet, Bootstrap 3)
- Backend in this repo: none (this UI calls a remote API)
- Backend contract: unchanged; requests go through the existing Node proxy endpoint to Elasticsearch
- Verified locally with:
  - `node v20.19.6`
  - `npm 10.8.2`

## Repository Layout

- `app/`: source files served in development
- `public/`: build output for deployment (generated by `gulp`)
- `app/trait-viz` (git submodule): required by current `gulp build` copy step

## Local Setup

1. Clone repo and enter it.
2. Initialize submodules (required for build):

```bash
git submodule update --init --recursive
```

3. Install dependencies:

```bash
npm install
```

4. Start local dev server:

```bash
npm start
```

This serves `./app` at <http://localhost:8000>.

## Build and Deploy

Build static output into `public/`:

```bash
npx gulp clean
npx gulp build
```

Notes:
- `gulp build` currently expects `app/trait-viz/lib/*` to exist.
- Any static host (Netlify, Nginx, Apache, S3+CloudFront, etc.) can serve the `public/` directory.

## Backend API Calls (Brief)

The UI builds Elasticsearch-style JSON queries client-side and posts them to the existing proxy endpoint.

### 1) Search + Facets (table view)

- Endpoint:
  - `POST https://biscicol.org/phenobase/api/v1/query//phenobase2/_search?size={pageSize}&from={offset}`
- Caller:
  - `fetchResults()` in `app/app.core.js`
- Payload shape:
  - `requestData = { query: {...}, aggs: {...} }`
  - `query` is composed from selected filters (scientific name, data source, family/genus, phenophase, year range, presence, geo bbox)
  - `aggs` drives sidebar facets and totals (`datasource_0`, `mappedTraits_1`, `family_2`, `genus_3`)

### 2) Stats view

- Endpoint:
  - `POST https://biscicol.org/phenobase/api/v1/query//phenobase2/_search?size=15&from=0`
- Caller:
  - `fetchStatsData()` in `app/app.stats.js`
- Payload:
  - same `requestData` object as table view
- Response usage:
  - uses `aggregations.*.buckets` to render distribution tables

### 3) Map points (manual render)

- Endpoint:
  - `POST https://biscicol.org/phenobase/api/v1/query//phenobase2/_search?size={batchSize}&from={offset}`
- Caller:
  - `loadMapDataIncrementally(true)` in `app/app.map.js` (triggered only by **Render Results**)
- Payload shape:
  - `{ query, _source: ["latitude","longitude","scientificName","mappedTraits","year","dataSource"], track_total_hits: true }`
- Behavior:
  - incremental batching, browser-safe chunked rendering, hard cap at **10,000** records per render pass

### 4) Download

- Endpoint pattern:
  - `GET https://biscicol.org/phenobase/api/v1/download/_search?q={luceneQuery}&limit=100000`
- Caller:
  - `updateDownloadLink()` in `app/app.core.js`
- Query source:
  - current JSON query is converted to Lucene syntax client-side, then used as `q=`

## Current UI Highlights

- Scientific name search
- Data source facet
- Year range slider (1800 to current year)
- Presence mode (`both`, `present`, `absent`) with source-based locking for present-only sources
- Phenophase mode toggle (`Simple terms` vs `All traits`) with mutual exclusivity behavior
- Geographic filter with numeric bounds (4 decimal places) + map bbox drawing
- Query summary text shown next to "Showing ..."
- Map rendering is manual via **Render Results** and does not auto-refresh points on filter changes
